# CRM Nexora — وثيقة متطلبات المنتج (ميدان الدعاية الطبية)

> مصدر الحقيقة للمنتج. آخر تحديث من مؤسس/صاحب المنتج. أي تنفيذ يلتزم بهذا السياق ما لم يُلغَ صراحة.

## الهدف الأساسي

إحكام الرقابة الميدانية على مناديب الدعاية الطبية أثناء ساعات العمل، تتبع خط السير الفعلي، توثيق الزيارات بدقة، وضبط عهدة الأدوية والهدايا المنصرفة لكل طبيب وصيدلية.

السوق المستهدف الابتدائي: شبين الكوم / المنوفية / مصر (حسب قواعد العمل المحلية للمشروع).

## أ. الأمان ومنع التلاعب (Security & Anti-Fraud)

| متطلب | التفاصيل |
|--------|-----------|
| Multi-Tenant Login | خطوة 1: كود الشركة → خطوة 2: اسم المستخدم + كلمة المرور |
| Device ID Binding | ربط حساب المندوب بـ Device ID عند أول دخول؛ أي جهاز آخر = رفض فوري + إشعار تحذيري للأدمن |
| First-login sync | عند أول دخول: مزامنة البيانات المحلية مع السيرفر |
| Anti-Fake GPS | اكتشاف تطبيقات الموقع الوهمي وإخطار الإدارة فوراً |
| Live Route & Device Status | تتبع خط سير المندوب على الخريطة طوال ساعات العمل |
| Offline & Auto-Sync | تسجيل زيارات/تحركات بدون إنترنت؛ مزامنة تلقائية عند عودة الشبكة؛ الاعتماد على توقيت موثوق (ضد التلاعب بساعة الهاتف) |

## ب. الدوام، التخطيط، وخطوط السير (Attendance & Routing)

### Check-in / Check-out

- مرن حسب سياسة الشركة.
- الحضور/الانصراف **يدويان** من الشاشة الرئيسية: زر **بدء الدوام** أو **إنهاء الدوام**.
- عند الضغط يُسجَّل الوقت و`lat`/`lng` للموقع الحالي (ليس مربوطًا بأول/آخر زيارة).
- (سابقًا كان الربط بأول/آخر زيارة — ملغى لصالح التسجيل اليدوي.)

### أنواع الزيارات (Visit kinds)

| النوع | المعنى |
|--------|--------|
| **Planning** | المندوب يختار زيارة أو أكثر من الحسابات المتاحة، يحدد الوقت، يقدّم طلباً، وينتظر موافقة الأدمن. عند الموافقة تتحول إلى **Planned**. |
| **Planned** | خطة زيارات أدخلها المندوب أو الأدمن وتم اعتمادها مسبقاً من الإدارة. |
| **Unplanned** | زيارات غير مخططة يضيفها المندوب أثناء اليوم (اعتذار طبيب، عميل طارئ، استغلال الوقت). |

### إضافة حساب جديد (Account)

- أنواع: طبيب، عيادة، مستشفى، … (قابلة للتوسع).
- المندوب يدخل بيانات حساب جديد لأول مرة ويقدّم طلباً للأدمن للموافقة.

## ج. تنفيذ الزيارة و DCR (Visit Execution)

### كارت الزيارات المعلقة (Pending Visits Card)

- على الشاشة الرئيسية: زيارات جارية أو معلقة.
- خياران: **Continue** (استكمال) أو **Cancel** (إلغاء).

### حقول الزيارة المشتركة (نموذج الدومين)

كل زيارة تحمل (على الأقل):

- `id`, `backendId`
- `date`, `time`
- `city`, `region`, `address`
- `account` (نص حر: طبيب / عيادة / مستشفى / … — ليس sealed type)
- `placeName`, `specialty`
- `shift` (AM / PM)
- `visitType` (Single / Double) — عند Double: مشرف/supervisor مطلوب
- قوائم: `gifts` (مع كمية)، `products`/`samples` (مع كمية)
- مرفقات: ملاحظة صوتية + صور (في الدومين كـ refs؛ البايتات/Uri في طبقات data/UI)
- `syncStatus` (Synced / NotSynced)
- حالة سير العمل workflow (Scheduled / InProgress / PendingApproval / …) منفصلة عن المزامنة

## مبادئ تقنية متفق عليها مع الكود الحالي

- Clean Architecture + MVI + Compose.
- نماذج الزيارة: `sealed class Visit` بأنواع Planning / Planned / Unplanned مع حقول مشتركة `abstract` (ليس god-object كله null).
- لا `ByteArray` / `Uri` على كيانات الـ domain.
- Offline-first و`SyncStatus` جزء من نموذج الزيارة/التحركات.

## خارج نطاق وثيقة الواجهة الحالية

تفاصيل API، أسماء endpoints، وتصميم شاشات Figma الكاملة تُضاف لاحقاً دون تغيير الهدف أعلاه.
